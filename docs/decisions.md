# Decisions

- Base on MOBAI547800/abaqus-mcp-server (MIT): subprocess design, 85 tests, best fit in docs/prior-art.md. Only four ideas taken; no unrelated files.
- rutwikg (AGPL): concepts only, no code.
- Server runs on the host; Abaqus runs in the VM; ssh/scp is the only link (no socket bridge, no exec server).
- Sync `subprocess.run` with timeout in the transport: ssh calls are one-shot, no async needed.
- Transport is one class with run/put/get; tests inject a fake.
- Every VM command line is built from names matching `[A-Za-z0-9_-]` (files: no `/`, `\`, `..`): no shell injection. Remote shell is Windows PowerShell 5.1: every VM command is written as PowerShell, paths as single-quoted literals (`psq`).
- One job = one VM dir `<work_vm>\<slug>-<hash>\<job>` and one host dir `<project>/<job>`; the project is set per session with `set_project` (specs/done/003-vm-sandbox.md C7).
- License guard is a TCP connect to license_host:license_port (4 s), `abaqus-vpn up` (15 s cap) once, second probe (4 s): at most 23 s.
- `abaqus information=release` does not touch the license server, so it is not used as a probe.
- Scripts inside Abaqus print one JSON document between markers; the server parses only that part.
- ODB queries use `abaqus python` (no CAE token); model_summary, model_views and viewport use `cae noGUI` (kernel needed).
- ODB is opened `readOnly=True` and closed in `finally`; value count is capped.
- Job status comes from .sta/.msg/.lck text; the exit code is not trusted (a launcher can print an error and exit 0).
- Stale .lck/.sta/.msg/.dat/.odb are deleted before submit.
- submit_job from a .cae writes the .inp with a noGUI script, then runs the same `abaqus job=` path.
- Background submit uses `Invoke-CimMethod Win32_Process Create`: Start-Process children die when the ssh session closes; verified on the VM with a `ping -n 40` child (2026-10-28).
- viewport output name has no dot; no maximize() under noGUI.
- Kernel scripts target Python 3.10 (SMApy/python3.10 in the 2026 install).
- `mcp<2`: FastMCP lives in mcp 1.x; mcp 2.x renamed it.
- Fixtures: ok/failed/running/nobc are hand-written (no usable real files in the MIT clone, rutwikg's are AGPL); tests/fixtures/upsetting/ holds real .sta/.msg/.dat from the C7 runs.
- E2E test is gated by ABAQUS_E2E=1 and drives the server through the stdio MCP client.
- Install: `setup.exe --silent <UserIntentions.xml>` (flag found in InstallData/installer/inst/win_b64/code/bin/DSYInsEngine.dll); XML copied from the host install's UserIntentions_CODE.xml with the license host templated.
- `abaqus_cmd` is the full path `C:\Program Files\SIMULIA\Commands\abaqus.bat`: no dependence on the machine PATH, sshd restarts or WMI environments. The PATH edit in install-abaqus.ps1 stays for interactive use.
- odb_query and model_summary scripts write JSON to a file in the job dir and the server fetches it: stdout is truncated at max_output.
- fs-abaqus is split-tunnel (`ipv4.never-default yes`): a full tunnel cut other internet traffic, including the Claude API.
- ssh ControlMaster not adopted: every call is one-shot and the VM is on a local libvirt network, so connection setup is cheap.
- GUI is RDP to the VM as user `abaqus` (same account as ssh, so GUI and MCP share one workspace); `./setup.sh gui` sets fDenyTSConnections=0 and the Remote Desktop firewall group over ssh and prints `unchanged` on a rerun. It is outside the default stage run because it needs a running VM.
- NLA stays on: xfreerdp3 does CredSSP with the local account; `/cert:ignore` because the VM certificate is self-signed on a host-only libvirt NAT.
- `bin/abaqus-gui` passes every xfreerdp3 argument, the password included, on stdin (`/args-from:stdin`, which accepts no other argument): verified with `ps -eo args` that the password is not visible.
- CAE starts from a desktop shortcut "Abaqus CAE (mesa)" (`abaqus.bat cae -mesa`) made by `./setup.sh gui`; qxl has no 3D, so `-mesa` is always on. No autostart and no RemoteApp: an alternate shell would drop the desktop.
- `/dynamic-resolution` (window resize follows into the VM) and `+clipboard`; `/smart-sizing` is mutually exclusive with dynamic resolution in xfreerdp3.
- job_status convergence (C5): one .sta row is one attempt; attempts, max/mean equilibrium iterations and severe-iteration sum count all rows; increments done, smallest and last increment and step time use rows without `U`.
- .msg warning "first increment" is the last `INCREMENT n STARTS` (or `STEP s INCREMENT n`) line above the first occurrence; unnamed warnings are grouped by first line with numbers removed; output keeps 12 groups, the last 5 errors and 3 sample warnings to stay under 100 lines.
- With no .sta and no .msg, job_status reads `***ERROR` lines (plus 3 lines of context) from the .dat and reports failed.
- odb_history (C6) uses `abaqus python` and writes JSON to the job dir like odb_query; the 200-point cut keeps first, last, min and max and spreads the rest evenly; region is a substring match, so one RF2 query spans every matching region.
- model_summary replaces model_info (same kernel script path, richer JSON); model_info is removed, not aliased, and tests and README use the new name.
- The summary and view code live as plain functions in src/abaqus_mcp/kernel/{summary,views}.py, embedded into the kernel script as text; the noGUI script only opens the mdb and calls them, so a live session can call the same functions.
- Summary output is capped at 20 kB by re-running with smaller per-list limits (scale 1, .5, .25, .1, .03); each cut list is recorded as `omitted["dotted.path"] = n`.
- Loads, BCs and interactions hold no step data on the object: step, values and contact property come from the step state whose status is CREATED; a component is listed only when its `<name>State` is not UNSET.
- Abaqus 2026 names contact surfaces `main`/`secondary` (`master`/`slave` raise a keyword error), so the schema uses main and secondary.
- `sum` is shadowed by `from abaqus import *` in the kernel (rejects dict_values): kernel code adds in a loop.
- Instances cannot mix 3D and axisymmetric parts in one model, an independent instance needs an unmeshed part: the test .cae has a second model `Solid` for the 3D independent instance.
- model_views highlights through a temporary display group coloured by the `Display group` colour mapping; `enableMultipleColors()` gave blank PNGs under noGUI, and Set/Surface colour-mapping overrides changed nothing.
- model_views PNG names are `<job>_views[_<highlight>]_{iso,front,top}.png`; the view PNGs are fetched to <project>/<job>/.
- Session libvirt (qemu:///session) with passt user networking and port forwards on 127.0.0.1; no system network, no static IP. Every ssh and scp call passes `-F <state_dir>/ssh_config`; `~/.ssh` is not edited (specs/done/003-vm-sandbox.md C2, C3).
- Defaults live once in `src/abaqus_mcp/config.py`; `python -m abaqus_mcp.config --print` gives shell-sourceable KEY=value lines to setup.sh, bin/ and vm/*.sh. Fixed URLs and the forward address are in `vm/sources.env`.
- `set_project` slug: characters outside `[A-Za-z0-9_-]` are dropped from the basename (`project` when nothing is left); a path outside `$HOME` after symlink resolution is refused; a new directory is created.
- A bare file name given to `run_script`, `submit_job(inp_file, cae_file)` is looked up in the project directory; a bare `cae_file` absent there is a file already in the VM job dir.
- `./setup.sh uninstall` asks before deleting; it refuses when `state_dir` has no `.abaqus-mcp-setup` marker, or is `$HOME`, `/`, the repo or a parent of it.
- Native Windows (specs/004-windows-native.md): config `transport = "local"` (default on Windows) runs the same PowerShell commands through `powershell.exe -EncodedCommand` (base64 UTF-16LE, so no command-line quoting), prefixed with UTF-8 console output and `$ProgressPreference='SilentlyContinue'`; put/get are local file copies. The Service and the tool code are unchanged.
- On Windows the work folder stays `C:\abaqus-work` (config `work_vm`), apart from the project folder: Abaqus fails on paths with spaces or non-ASCII characters, and user folders often have both.
- Windows licence host: config, else the first `host:port` line of `C:\ProgramData\DassaultSystemes\Licenses\DSLicSrv.txt`; with neither the probe is skipped (`not checked`). `vpn_cmd` is empty on Windows: a closed port asks the user to connect the VPN.
- Windows Abaqus command: `abaqus` on PATH, else `C:\Program Files\SIMULIA\Commands\abaqus.bat`, else `C:\SIMULIA\Commands\abaqus.bat`.
- The live plug-in reads its folder from `live_dir.txt` next to it (written by setup from `work_vm`); `ABAQUS_MCP_LIVE_DIR` still wins.
- `setup-windows.cmd` starts `setup-windows.ps1` with `-ExecutionPolicy Bypass`: the default policy (Restricted) blocks a double-clicked .ps1, and changing the policy would touch the user's settings. The .cmd is stored with CRLF (`.gitattributes`).
- Windows setup copies the skill and the plug-in (hash compare) instead of linking: symlinks need admin or Developer Mode.
- `abaqus-mcp --check` (doctor) runs through the configured transport, so one check covers Windows and the VM; it exits 1 on any FAIL and prints a fix line per FAIL.
- Number output from PowerShell goes through `"$(...)"` (invariant culture): under sl-SI a bare double prints `0,53` (checked in the VM). A local command past its timeout is ended with `taskkill /F /T`: `subprocess.run` on Windows kills only powershell.exe and then waits for the pipes the Abaqus children hold.
- Transport children get `stdin=DEVNULL` and output is decoded as UTF-8: with the inherited stdin (the MCP JSON-RPC pipe) a local `abaqus cae noGUI` hung with no CPU; with the Windows code page `Ž č` came back as mojibake.
- `tests/test_convergence.py` is skipped on Windows: its oracle is awk and grep, which Windows lacks; the parser is pure Python and covered on Linux.
- Live plug-in timer: `addTimeout(ms, target, MKUINT(id, SEL_TIMEOUT))`; abaqusGui 2026 has no `FXSEL`. The kernel writes the result to `log/<id>.json` and `outbox/<id>.json`; the dispatcher takes `log/<id>.json` as done, since the MCP deletes the outbox file once read.
- Lean output and native partitioning (specs/005-lean-tools-native-partition.md): `run_script` returns `print_output` and `stdout` with runs of identical lines collapsed (` [xN]`) and the last `print_cap` characters (default 4000); `stderr` and `traceback` only on failure. Every result stays in the client context for the rest of a session, so output size is paid on every later turn.
- `run_script` runs `_mcp_run.py`, which does `import caeModules`, puts the job dir on `sys.path` and execs the user script in a fresh namespace with the real builtins. `from caeModules import *` replaced `sum` (field-log entry 8); a bare `import caeModules` is enough for `mdb.openStep` (probe 2026-10-29).
- Partition and mesh helpers live in one kernel module, `src/abaqus_mcp/kernel/abqmcp.py`, uploaded with every `run_script` and once per server process to the live dir (the live kernel puts that dir on `sys.path`); no tool per helper, so the tool schemas stay at 9.5 kB.
- `abqmcp.import_solid` merges a multi-body STEP as one part per body (`combine=OFF, bodyNum=i`) plus `InstanceFromBooleanMerge(keepIntersections=ON)`: `combine=ON` left duplicate vertices (field-log entry 7). The body count is `openStep(...).numberOfParts`.
- `abqmcp.mesh_plan` tries `setMeshControls(technique=...)` per cell: Abaqus raises "Some regions cannot be Mapped." for an unmappable cell and keeps the old control, so the call itself is the check.
- `model_views` defaults to 900 x 600 (about 720 image tokens a PNG); a list of highlights draws one iso PNG per name in one CAE run.
- `model_summary(only=...)` filters on the server after the full summary is built; `node_limit` (default 0, off) is a server config value checked against `mesh.nodes`, the mdb count, which excludes reference-point nodes the solver adds.
